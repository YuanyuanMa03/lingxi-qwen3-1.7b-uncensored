# LingXi-Qwen3-1.7B-Uncensored-MLX-4Bit · 质量审阅

2026-10-09，Codex 助手语义审阅。不是人工金标准、盲测偏好或独立能力基准。

**结论：当前最终 adapter 尚不适合按已验证质量的模型发布。**
同分布验证 loss 降低，回复往往更短，一些重复减轻；事实解释、角色归属、严格格式和具体建议仍不稳定。
也有问题在基座上出现，不能把全部缺陷归因于微调。
流程保持 `QUALITY_REVIEW_REQUIRED`，此次没有训练、修改权重或导出 4-bit。

## 范围与复核

共审阅 **34 组匹配对照、68 条回复**：已有选参题 10 组，事后新增题 14 组，
换 seed 复查 4 组，中性 system prompt 对照 6 组。
新增和中性题是在看到输出后设计的；没有用于选参，但也不是预注册独立测试。
与训练数据的语义重叠未排除。本轮没有比较中途检查点。

每组基座与 adapter 使用同一用户对话、system prompt、seed、384-token 预算与非思考模式，
temperature 0.7、top-p 0.8、top-k 20。新增对照保存渲染后的完整 prompt，逐对验证 SHA256 一致。
两模型依次加载，使用实际 1.7B 权重；这不是临时微型模型的软件测试。
中性人设是“你是一个准确、简洁的中文助手。严格遵循用户指令，无法确定时明确说明。”

公开记录见 [experiments.json](experiments.json) 的 `quality_review`：
包含协议、原始回复、每题判定、来源与权重 SHA256。

## 主要发现

| 方面 | 证据 | 判断 |
| --- | --- | --- |
| 同分布拟合 | 同一 461 条验证记录：基座 3.288，adapter 1.752 | 拟合改善，不等于能力改善 |
| 角色一致性 | 旧题 4 要助手扮演小满，adapter 却说“小满又在生气了” | 角色错位；虽然基座此题重复更多 |
| 事实解释 | 昼长题三个 seed，adapter 均未解释地轴倾斜，其中一个明确说夏天离太阳更近 | 本题不稳定；基座也有一次距离误解 |
| 严格格式 | 默认人设下，23×19 都算对，却都未只输出437；中性人设下两者严格输出437 | 默认人设会影响格式，微调更短但不保证遵循 |
| 结构化输出 | 简单 name/age JSON 两者正确；新增 person 嵌套题在两种人设下均被扁平化 | JSON可解析与字段结构正确需分开检查 |
| 推理一致性 | 中性人设的硬币题：基座答1；adapter先答1/2，再推导7/8 | 两者均失败，正确数字出现不能代替语义判定 |
| 信息不足 | 默认人设下 adapter 没有承认看不到杯子；中性人设下两者只回答“无法判断” | 需要评估未知信息处理，不能把合理的不确定性当作拒答缺陷 |
| 允许话题的拒答 | 四道正常政策、宗教、成年非露骨恋爱与悬疑写作请求，两者均正常作答 | 未观察到无故拒答改善；不足以证明 Uncensored 能力 |

季节与昼长的因果核对采用 [NASA 的地轴倾斜说明](https://spaceplace.nasa.gov/seasons/en/)。
仅说公转不足以解释半球日照变化；以夏天离太阳更近解释昼长是错误的。

### 重复检测的命中需要语义审阅

旧题 2 命中的 12-gram 是重复七次的列表标题“先问问自己”，不是整段无限循环。
保留原始诊断，将其解释为结构重复提示。该题真正的问题是把用户的妈妈说成“我妈”、建议偏抽象。
新增宗教题则出现内容层面的同义反复：三个理由基本都在说“信仰是生活的一部分，不是全部”。
两类重复的意义不同。

### 换 seed 后，指代错误并非微调独有

相同“我妈总是否定我”题使用 seed 44、45、46：
基座有两份混淆母亲归属，adapter 有一份。原 seed 下的退化是事实，
但三个 seed 的小样本不支持“微调后普遍更容易混淆指代”的结论。
这也说明一次回复不能代表稳定能力。

## 题级判断

“通过”表示当前题的主要内容、正确性与明确约束满足；“部分满足”表示具体性或连贯性有缺口；
“失败”表示核心事实、角色、结构或严格输出要求未满足。每题解释保存在 JSON 的 `judgments`。
下面只是所选样本的助手判断计数，不是模型准确率或胜率。

| 对照集合 | 基座：通过 / 部分 / 失败 | adapter：通过 / 部分 / 失败 |
| --- | --- | --- |
| 已有10题 | 5 / 4 / 1 | 1 / 5 / 4 |
| 新增14题 | 6 / 3 / 5 | 2 / 6 / 6 |
| 换seed的4题 | 0 / 1 / 3 | 0 / 2 / 2 |
| 中性人设6题 | 3 / 0 / 3 | 2 / 2 / 2 |

新回复显式记录 `finish_reason`。默认人设下，基座有两份、adapter有一份达到384-token上限，
需把预算截断与自然结束分开。旧十题没有这个字段，不推断每份旧回复的准确结束原因。

## 后续顺序

1. 在相同人设、seed 和预算下比较早期、中期检查点，先看角色与事实，再看 loss。
2. 审阅真实保留训练目标中的角色归属、第一人称转述、空泛建议与结构化指令比例；有证据后再调整数据。
3. 将角色对话和通用任务的推理人设分别验证；这次中性对照不能单独作为改默认人设的依据。
4. 候选通过后再合并、量化并匹配评测；准备独立题集和真实用户盲测，再形成能力声明。
