# 数据与训练方法诊断

2026-10-09，针对[质量审阅](QUALITY.md)中的失败做事后诊断。结论是：**数据中有直接可见的语义缺陷，训练 loss 有可复现的 padding 边界缺陷，整轮训练也出现了部分能力漂移。** 这些发现尚未通过重新训练的消融分离贡献，不能把所有问题归为单一原因。

本轮没有训练或修改权重、数据、原始指标。全量检查 23,052 条保留记录的模板与监督区间，重放来源映射，并从既有检查点生成 16 条匹配回复。助手检查了固定随机样本及命中样本；不是人工金标准或全量数据语义标注。

## 数据：结构合法，但不一定是完整问答

保留数据均可映射回原来源，未发现来源映射缺失或歧义。训练集实际构成为：

| 来源 | 训练记录 | 记录占比 | 最后回复的真实监督 token 占比 |
| --- | ---: | ---: | ---: |
| Dolphin | 13,699 | 60.64% | 54.84% |
| 中文情感 | 5,621 | 24.88% | 37.53% |
| 中文角色 | 3,271 | 14.48% | 7.62% |

这里的 token 包含模板中的空 think 与结束标记，不包含 padding。上游 batch=1 时先按每条记录的 token 计算平均 loss，再平均累计梯度；token 占比不是梯度权重占比。

### 情感数据存在聊天碎片和说话人混合

以下是实际保留训练记录的语义检查。行号从 1 开始；原字段与清洗后的目标逐项匹配，问题在原始来源中已存在。公开记录只提供定位、摘要和 SHA256，完整原文留在本地。

| train.jsonl 行号 | 原 emotional_support.jsonl 行号 | 发现 |
| ---: | ---: | --- |
| 17,708 | 527 | user 字段是助手介绍“下面给几个方法”的开头，assistant 是这段介绍的续文，缺少真实用户请求 |
| 18,692 | 966 | user 字段混入助手提问、用户追问与助手回答的开头；assistant 从回答中间继续 |
| 9,164 | 2,425 | 目标只有一个“结论”标题，没有结论内容 |
| 17,388 | 205 | user 是助手的安慰与提问；assistant 先写用户反驳，再接助手回应，跨越了两位说话人 |
| 16,365 | 4,896 | assistant 先包含被回应者的分析，再接助手对该分析的赞扬，角色边界混合 |

这不是空 think 前缀或 JSONL 角色排列的问题。预处理只校验 `user/assistant` 字段交替、长度和精确重复，无法识别字段内部的说话人。`clean_emotional_output` 去除显式思考段，也不能恢复丢失的对话边界。

5,621 条训练情感记录中，5,495 条标注来自 Gemini；662 条目标含 `Gemini姐姐`，1,018 条含“小公主”。这些是字面统计，不能自动等同于错误率，但说明训练身份与当前默认博主人设并未统一。随机抽样还观察到过度赞扬、依赖未提供的前文及无来源的引用标记。调整前应逐条审核，不能按称呼批量删除。

训练集没有一条 system 与当前 `PERSONA` 完全一致；情感与 Dolphin 记录没有显式 system，角色记录使用各自角色描述。这不是语法错误，但推理默认统一加入情感博主人设，属于需要单独验证的条件变化。

### 通用任务覆盖与定位有缺口

Dolphin 的 13,699 条训练回复中，仅 4 条达到“汉字占字符数大于 30%”的阈值。该阈值不是完整语言分类；随机抽样主要是英文任务、翻译、情感分类、改标点等，并常在 user 字段要求详细解释。来源名含 uncensored 不能证明当前选中的记录训练了该能力。

全训练集有两条可直接解析为 JSON 数组的回复，没有可直接解析为 JSON 对象的回复。此检查不包含围栏代码或夹在解释中的 JSON，不能当作所有结构化任务的数量。严格格式与中文基础任务的覆盖需要重新建立，而不能指望一般英文任务自然保留这些能力。

还确认一条算术错误：训练行 15,656 的十个数均值目标为 116.599，按给定数字实际为 116.419。单条证据不能推断全库数学错误率，但“普通问答”来源也需要正确性检查。

### 角色监督与验证不足

全部 3,271 条训练角色记录都是多轮对话，当前 `mask_prompt=True` 只监督最后一个 assistant；此前 9,813 个 assistant 回合属于上下文。最后回复的 token 量仅占全训练真实监督 token 的 7.62%。这是上游支持的最后回复训练方式，不是 mask 错位；它与学习丰富的角色开场、角色建立并不等价。

训练与验证之间没有完全相同的整段对话，但有 1 个相同 prompt、10 个相同最后回复。53 条角色验证记录中，48 条与训练集共用角色 system 描述，涉及 47 个描述组；共享描述不能证明对话完全泄漏，也不能支持对未见角色的泛化结论。

所有 113 条情感验证记录的原 `conversation_title` 都为空，无法据此验证同一原始会话的隔离。空标题表示缺失元数据，不能把它们当作一段相同会话。当前验证是随机同分布划分，不是独立能力验证。

## 训练实现：确认一个目标边界缺陷

全量检查结果：prompt 与完整序列前缀错位 **0**，超过训练长度 **0**，无监督目标 **0**；最大完整序列为 1,400 token，低于训练上限 1,536。Qwen 的 `/no_think` 与空 think 方式符合[官方非思考训练方案](https://github.com/QwenLM/Qwen3/blob/main/docs/source/training/ms_swift.md)。因此，本次证据不支持“主要问题是模板缺前缀或回复被截断”。

但 [MLX-LM v0.31.3 的 default_loss](https://github.com/ml-explore/mlx-lm/blob/v0.31.3/mlx_lm/tuner/trainer.py) 使用 `steps <= sequence_length`，实际应在真实序列的最后一个 token 结束监督。上游 batch 在真实序列后补 0；现有边界使后面第一个 padding 也成为 next-token 目标，Qwen token 0 解码为 `!`。

已下载官方 v0.31.3 的 trainer、datasets、lora 源码，与本地安装文件逐字节一致。这是当前使用的上游实现行为。

最小复现调用真实 `ChatDataset`、`iterate_batches`、`default_loss`，用均匀 logits 只检查目标计数，无需加载模型权重：

```python
import mlx.core as mx
from transformers import AutoTokenizer
from mlx_lm.tuner.datasets import ChatDataset
from mlx_lm.tuner.trainer import iterate_batches, default_loss
from lingxi.persona import qwen_messages

tok = AutoTokenizer.from_pretrained("models/Qwen3-1.7B")
row = {"messages": qwen_messages([
    {"role": "user", "content": "只输出结果：2+2"},
    {"role": "assistant", "content": "4"},
])}
dataset = ChatDataset([row], tok, mask_prompt=True)
tokens, offset = dataset.process(row)
batch, lengths = next(iterate_batches([dataset.process(row)], 1, 1536))

class Uniform:
    def __call__(self, x):
        return mx.zeros((*x.shape, len(tok)))

_, count = default_loss(Uniform(), batch, lengths)
assert count.item() == len(tokens) - offset
```

当前断言失败：真实目标为 7 token，上游计数为 8；监督尾部为 `4<|im_end|>\n!`。本轮保留训练/验证记录全部命中这个额外 padding。训练集逐条求和：真实目标 2,517,780，上游目标 2,540,371，多 22,591 个。这里只计算训练集各遍历一次；原训练日志的 2,540,402 来自 22,592 个微批次。原始统计保持不变，后续评测应区分历史 loss 与修正后的 loss。

**这是必须修正的训练契约缺陷，但尚未证明它导致本次角色与事实错误。** 它位于 EOS 之后，不能仅据此推断生成时必然输出感叹号或循环。本轮保留失败复现，没有修改 site-packages 或训练入口。

## 训练预算：部分质量退化可复现

在同一整轮训练中选早期 2,048 微批次（128 次更新）和中期 12,288（768 次更新），每个生成相同 8 题；与基座、最终模型 22,592（1,412 次更新）的原回复比较。人设、prompt、seed、384-token 预算与采样相同，新 prompt SHA256 匹配。采样符合 [Qwen 的非思考建议](https://huggingface.co/Qwen/Qwen3-1.7B)。这是根据已见失败选出的事后诊断，不能当作独立模型排名。

| 题目 | 早期 | 中期 | 最终 | 含义 |
| --- | --- | --- | --- | --- |
| 夏天昼长 | 地轴倾斜与北半球朝向，48 字 | 模糊的地日夹角，未说明地轴，55 字 | 只有公转解释 | 本题随训练丢失关键因果，早期符合约束 |
| 女朋友小满 | 第一人称，但表达重复、性格弱 | 语义突兀 | 角色归属混乱 | 早期在角色归属上更稳，仍未全面合格 |
| 妈妈否定决定 | 混淆用户与助手妈妈 | 将经历说成自己的 | 同类混淆 | 早期已经有缺陷，不能只归为训练尾段 |
| 嵌套 JSON | 扁平化 | 扁平化 | 扁平化 | 基座也失败，延长训练未补足能力 |
| 硬币概率 | 7/8，推导正确，格式超出要求 | 7/8，但把“零次反面”说成“三次反面” | 7/8，解释正确，格式仍失败 | 变化非单调，不能宣称全面持续退化 |
| 不可见杯子 | 声称看见，再说无法判断 | 声称看见并猜颜色 | 未承认信息不足 | 数据、默认人设和已有基座能力均需检查 |

另外两题为师尊角色与只输出乘法结果：早期师尊也有段落重复，中期仍重复；算术各点数值正确，但均违反严格格式。新生成的 16 条均正常停止，没有达到预算上限。

固定全量验证 loss 从 2,048 微批次更新前的 2.559 降到中期更新前的 1.771，再到最终保存权重的 1.752。检查点在更新后保存，回调值在更新前测量，二者不是完全相同权重。走势支持“同分布拟合改善，同时部分题目退化”，不构成全局灾难性遗忘或经典过拟合的证明。

整轮预算约为此前 1,024 微批次试跑的 22 倍，warmup/cosine 也相应延长。相同峰值学习率不代表相同总训练影响。短程回复合格不能直接批准整轮训练后的能力；需要按检查点验证。

## 原因判断与修复顺序

| 假设 | 证据状态 |
| --- | --- |
| 数据语义质量与目标分布有问题 | 已确认字段混合、碎片、错误目标和覆盖缺口；是否主导具体模型缺陷仍需数据消融 |
| 模板前缀错位或训练截断 | 本轮全量检查不支持 |
| loss 监督 padding | 已复现、全量计数确认；生成质量贡献尚未隔离 |
| 扩大训练预算造成部分漂移 | 同一训练轨迹的匹配题支持，不能扩展为所有能力下降 |
| 默认人设冲突 | 上轮中性对照改善算术严格格式与未知信息处理，但没有修复嵌套 JSON 或推理一致性 |
| 学习率、rank 或 optimizer 是唯一原因 | 证据不足；本轮没有新增训练消融 |

下一轮先恢复或筛出完整、说话人明确的问答，保留来源会话 ID；无法恢复边界的记录隔离审查。重新建立有质量验收的中文通用/格式/角色样本和分组验证，核对监督范围及配比。再修正 padding loss 边界，运行最小失败测试与实际小模型训练契约测试。最后从同一基座做固定预算的数据对照与检查点评测，再决定学习率、训练长度及最后回复/多轮监督方案；每次只改变一个待检验因素。

当前保留 `QUALITY_REVIEW_REQUIRED`。没有新学习率“最优”结论，没有删除样本，没有宣布任一检查点可发布。
